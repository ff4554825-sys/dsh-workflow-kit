# dsh-workflow-kit v1.2 字段真相矩阵

本文是存储形状、档位约束、脚手架补全和读模型的唯一真相。散文说明与本文冲突时，以本文为准。

v1.2 规则编号用 V，不用 S。S1–S10 冻结给 legacy 行，语义不再改。见 §7、§8。

图例：

| 标记 | 含义 |
|---|---|
| REQ | 键必须出现，且满足类型与非空约束 |
| OPT | 可省略；省略等价于「未提供」，不得写成空字符串充数 |
| COND | 满足「条件」列时升为 REQ，否则不得出现或必须省略 |
| FORBID | 该档位禁止出现此键 |
| `T \| null` | 可空时必须显式写 `null`，不许用缺列表示可空 |

写入方：

| 写入方 | 含义 |
|---|---|
| Auto | 仅脚手架 / CLI 可写。模型手写或篡改即违规 |
| Model | 执行 Agent 提供。脚手架只在本文「补全规则」允许时填默认值 |
| External | 外部裁决器、CI 或人工，经验收 CLI 落盘 |

空值两则（全局）：

- REQ 的字符串必须非空（去掉首尾空白后长度 ≥ 1）。
- REQ 的数组必须是数组。是否允许 `[]` 由该字段的「空数组」列决定，不从 REQ 推断。

## 1. 主记录 `record_type: "task"`

新写入的 task 一律带齐 Auto 字段。v1.2 新行禁止 `legacy: true`。历史行怎么冻结见 §8，不靠读取器补类型。

| # | 字段 | 类型 | 写入方 | lite | std | full | 空数组 / 空对象 | 条件与约束 |
|---|---|---|---|---|---|---|---|---|
| 1 | record_type | string | Auto | REQ | REQ | REQ | — | 固定 `"task"` |
| 2 | session_id | string | Auto | REQ | REQ | REQ | — | 分片 ID，环境注入 |
| 3 | seq | int | Auto | REQ | REQ | REQ | — | 分片内从 1 起严格 +1 |
| 4 | ts | string | Auto | REQ | REQ | REQ | — | ISO-8601 带时区；分片内单调不减 |
| 5 | executor_id | string | Auto | REQ | REQ | REQ | — | 执行者 ID。模型不填。accept 用它做身份隔离 |
| 6 | task | string | Model | REQ | REQ | REQ | — | 一句话目标，非空 |
| 7 | tier | string | Auto 或 Model | REQ | REQ | REQ | — | 枚举 `lite` / `std` / `full`。缺省规则见 §4 |
| 8 | tier_rule | string | Auto | OPT | REQ | REQ | — | 定级依据，如 `rule:T3`、`escalated:improve#4`、`default:lite` |
| 9 | status | string | Model | REQ | REQ | REQ | — | 枚举 `done` / `partial` / `blocked` |
| 10 | evidence | string | Model | REQ | REQ | REQ | — | 结果证据摘要。自由文本，受 §6 |
| 11 | corrects | object \| null | Model | OPT | OPT | OPT | — | 省略或 `null` 等价。有值时形如 `{session_id, seq}`，`session_id` 可省略表示本分片。目标必须真实存在（V4） |
| 12 | arbiter | string | Auto 或 Model | OPT | REQ | REQ | — | 如 `pytest`、`rubric:doc-v1`、`none`。lite 省略 ≠ `none`，见 §4 |
| 13 | arbiter_reason | string \| null | Model | COND | COND | COND | — | 仅当 `arbiter=="none"` 时 REQ 且非空；否则必须省略或 `null`（V7） |
| 14 | degraded | boolean | Auto 或 Model | OPT | REQ | REQ | — | lite 缺省由脚手架写 `false` |
| 15 | degraded_recovery | string \| null | Model | COND | COND | COND | — | 仅当 `degraded==true` 时 REQ 且非空；否则必须省略或 `null`（V8） |
| 16 | kill_action | object \| null | Model | OPT | OPT | REQ | — | `{cmd_or_check, expect, fail_signature}`，三键皆非空字符串。std 不强制。自由文本受 §6 |
| 17 | red_attempts | array\<object\> | Model | COND | COND | COND | 不允许 `[]` | 元素 `{attempt:int, sig:string, pointer:string}`。`pointer` 受 §6 |
| 18 | acceptance | array\<object\> | Model | OPT | REQ | REQ | lite 允许 `[]`；std/full 不允许 | 元素见 §1.1。std/full 长度 ≥ 1 |
| 19 | review | string | Model | FORBID | REQ | REQ | — | 本轮复盘，非空。lite 出现即 V2 失败 |
| 20 | improve | object \| null | Model | FORBID | OPT | REQ | — | 结构见 §1.2。full 必须出现且非 `null` |
| 21 | carryover | array\<string\> | Auto 或 Model | FORBID | OPT | REQ | 允许 `[]` | 未关闭项 ID。full 键必须在，没有遗留就写 `[]` |
| 22 | legacy | boolean | Auto | FORBID | FORBID | FORBID | — | v1.2 新行禁止此键。legacy 身份只由 §8 的 schema 事件划定 |

lite 上 Model 的最小键：`task`、`status`、`evidence`。其余 lite-REQ 由脚手架在落盘前写入。

### 1.1 `acceptance[]` 元素

| 键 | 类型 | 约束 |
|---|---|---|
| id | string | 本记录内唯一，非空 |
| criterion | string | 非空 |
| verdict | string | 落盘时只允许 `PENDING` / `UNKNOWN`。`PASS` / `FAIL` 只能由后续 accept 事件折叠得到，禁止模型在 task 行直接写死 |
| pointer | string | 非空，受 §6。相对路径、测试节点或 Run ID |

### 1.2 `improve` 对象

| 键 | 类型 | 约束 |
|---|---|---|
| id | string | 非空，作为 carryover 引用键 |
| window | int | ≥ 1 |
| finding | string | 非空 |
| severity | string | `P0` / `P1` / `P2` |
| action | string | 非空 |
| due | string | ISO-8601 日期 |
| restore | string | 非空，关闭条件 |
| closed | boolean | 新建必须为 `false` |

### 1.3 `red_attempts` 条件

| 档位 | 条件 | 要求 |
|---|---|---|
| lite | `status=="blocked"` | 键必须在，长度 ≥ 1，每条有非空 `sig` 与 `pointer` |
| lite | 其他 status | 必须省略 |
| std / full | `status=="blocked"` | 长度 ≥ 3，每条有非空 `sig` 与 `pointer` |
| std / full | 其他 status | OPT；若出现则长度 ≥ 1，元素结构同上 |

`blocked` 且条数不够：V5 失败，不得降级为 `partial` 蒙混。

## 2. 追加事件

与 task 写入同一分片，共享 `session_id`，`seq` 继续严格 +1。模型不能伪造这些行。

### 2.1 `record_type: "gate"`

每次门禁结束追加一行，全部 Auto。

| 字段 | 类型 | 约束 |
|---|---|---|
| record_type | string | 固定 `"gate"` |
| session_id | string | 本分片 |
| seq | int | 严格 +1 |
| target_seq | int | 只指向本分片已存在的 task。跨分片门禁不存在（V4） |
| ts | string | 本次门禁结束时间 |
| profile | string | `lite` / `code` / `doc` |
| stages | object | 键集合由 profile 决定，见下表。不得多写假阶段 |
| metrics_auto | object | `{rounds:int, red:int, tool_calls:int, aborted:int, source:string}`，`source` 必须为 `"auto"`（V9） |
| result | string | `PASS` / `FAIL` |

`stages` 每个出现的阶段值：`{exit_code:int, duration_ms:int, retries:int, timed_out:boolean}`。

| profile | 必须出现的阶段键 | 不得出现 |
|---|---|---|
| lite | `S` | `F1` `F2` `F3` |
| code | `S` `F1` `F2` `F3` | — |
| doc | `S` `F1` `F2` `F3` | — |

判定：

- 任一阶段 `timed_out=true` ⇒ 该阶段 `exit_code≠0`，且 `result=FAIL`。违反这条的 gate 行本身 V12 失败。
- `result=PASS` 当且仅当所有必须阶段的 `exit_code=0` 且无 `timed_out`。
- 同一 task 允许多条 gate。历史全保留。交付与否只看读模型里的最新一条。

`profile=lite` 不采集无意义的质量阈值；`metrics_auto` 仍要写，计数可为 0。

这里的阶段名 `S` 是门禁阶段 Schema，不是规则编号 S1。失败信息写阶段名时用 `stage:S`，规则编号仍用 `V*`。

### 2.2 `record_type: "accept"`

| 字段 | 类型 | 写入方 | 约束 |
|---|---|---|---|
| record_type | string | Auto | 固定 `"accept"` |
| session_id | string | Auto | 本分片（事件写在哪片，不是目标在哪片） |
| seq | int | Auto | 严格 +1 |
| target | object | External | `{session_id:string, seq:int, criterion_id?:string}` |
| ts | string | Auto | 签收时间 |
| reviewer | string | External | 非空，且 `reviewer ≠` 目标 task 的 `executor_id`（V10） |
| verdict | string | External | `PASS` / `FAIL` / `UNKNOWN`。禁止 `PENDING` |
| pointer | string | External | 非空，受 §6 |
| note | string \| null | External | OPT。出现则非空，受 §6 |

`criterion_id` 省略表示整单；出现则必须等于目标 task 上某个 `acceptance[].id`。

### 2.3 `record_type: "schema"`

一个分片至多一条 `spec=="1.2"` 的 schema 事件。字段见 §8。

## 4. 补全规则（零负担 lite 的验收标准）

脚手架在校验前做且只做下列补全。

1. 模型未传 `tier`：置 `tier="lite"`、`tier_rule="default:lite"`、`degraded=false`、`acceptance=[]`（模型已传 `acceptance` 则保留）。然后补 Auto 字段：`record_type`、`session_id`、`seq`、`ts`、`executor_id`。
2. 模型传入 `tier` 且值不是 `lite`：禁止改写成 lite，禁止用 lite 默认值填 std/full 的 REQ。缺什么就按该档失败。
3. 模型传入 `tier="lite"`：不降级、不升档。FORBID 键原样进入校验并失败。
4. `arbiter` 在 lite 上省略：保持省略。省略不是 `none`，不因此要求 `arbiter_reason`。只有显式 `arbiter="none"` 才触发 V7。
5. `status="blocked"` 时不自动编造 `red_attempts`。条数不够即失败。
6. Auto 字段若模型已传且与脚手架计算值不一致：V2 失败，不覆盖、不放行。涵盖 `seq`、`ts`、`session_id`、`executor_id`、`record_type`。

lite 验收标准：只提交 `task`、`status`、`evidence` 三个业务键，`status≠blocked`，且自由文本过 §6，则补全后 V2 必须通过，且同一次原子操作写入 `profile=lite` 的 gate（只含阶段 `S`）。除此之外不承诺「100% 通过」。

## 5. 读模型（折叠顺序）

存储只追加。下列视图是派生的，不回写日志。只折叠 v1.2 新行；legacy 行不进入这条链。

1. 按分片用 `seq` 排时间线；全局视图按 `(ts, session_id, seq)` 归并。
2. 更正先于验收。若记录 C 的 `corrects` 指向 T，则 T 的业务结论被 C 取代，T 的原文仍在。C 自身再被更正时，沿链走到终点；出现环即 V4 失败。跨分片目标不存在即 V4 失败，不得挂起成「待定」。不得指向 legacy 行。
3. accept 叠在更正之后的那条有效 task 上。
4. 分组键是 `(target.session_id, target.seq, criterion_id)`。组内按 accept 的 `ts` 取最新；`ts` 相同则取更大的 `seq`。
5. `criterion_id` 缺省的事件作用整单：把该 task 每条 acceptance 的 verdict 都设为该事件的 verdict。
6. 带 `criterion_id` 的事件只改对应条目。同一 task 上分项与整单并存时，分项优先于整单；没被分项点名的条目用最新整单 verdict；从无整单也从无分项的条目保持落盘时的 `PENDING` 或 `UNKNOWN`。
7. 最新 gate：同一 `target_seq` 上 `ts` 最大的 gate 行（并列取更大 `seq`）。

对外三个口径，互不混用，且只统计 v1.2 新行：

| 口径 | 条件 |
|---|---|
| delivered | 最新 gate 存在且 `result=PASS` |
| accepted | delivered，且折叠后每条 acceptance 的 verdict 都是 `PASS` |
| open | 其余（无 gate、最新 gate 为 FAIL、或仍有 `PENDING` / `FAIL` / `UNKNOWN`） |

`UNKNOWN` 不算通过。统计「完全验收通过」只计 `accepted`。

## 6. V11 自由文本边界

适用键：`evidence`、`review`、`note`、`pointer`、`kill_action.cmd_or_check`、`kill_action.expect`、`kill_action.fail_signature`、`red_attempts[].sig`、`red_attempts[].pointer`、`acceptance[].pointer`、`acceptance[].criterion`、`arbiter_reason`、`degraded_recovery`、`improve.finding`、`improve.action`、`improve.restore`。

- 禁止密钥、token、私钥、连接串、证件号、未脱敏的个人联系方式原文。
- 命中则该行校验失败，不得改写成打码后照写。调用方在进日志前自行脱敏；日志层只拒绝。
- 单键最长 2048 字符。更长的命令输出不进这些字段，只允许写「算法名 + 十六进制 hash + 截断后的前 256 字符」，hash 与截断都放在同一个字符串里。

## 7. 规则编号（V 前缀，不复用 S）

v1.1 校验器已经对外发出 S1–S10。v1.2 里若仍叫 S6/S7/S8/S10，失败签名和回归样例会对不上：这四条的判定面已经变了，其余几条也不是逐字相同。因此整表换编号，不做「只改冲突号、其余继续叫 S」的半套。

- S1–S10 的编号与语义冻结，只服务 legacy 行，不再扩写。
- v1.2 校验器只发出 V 号。禁止把旧 S 号重新定义成新语义。
- 失败信息格式：`GATE: FAIL (V6)`。不得再写 `GATE: FAIL (S6)` 表示 v1.2 规则。

| 编号 | v1.2 检查 | 与旧号的关系 |
|---|---|---|
| V1 | 分片内 seq 严格 +1，ts 单调不减 | 同 S1，编号仍分开 |
| V2 | 必填矩阵只认本文 §1–§3 | 取代 S2 的口头「8 / 17 字段」，不是 S2 的修订版 |
| V3 | 枚举与类型：tier、status、verdict、profile、result、severity，以及 gate 阶段的 exit / timed_out 组合 | 旧 S3 的超集，不沿用 S3 这个名字 |
| V4 | `corrects`、`target`、`target_seq` 必须落到已存在的行；gate 不得跨分片 | 旧 S4 的收紧 |
| V5 | `blocked` 举证：lite ≥ 1，std/full ≥ 3，见 §1.3 | 旧 S5 只约束 std/full |
| V6 | std/full 的 acceptance 长度 ≥ 1；元素含 id、criterion、落盘 verdict 仅为 PENDING 或 UNKNOWN、pointer 非空 | 与旧 S6 语义不同，所以不用 S6 |
| V7 | 仅 `arbiter=="none"` 要求 `arbiter_reason`。省略 arbiter 不触发 | 与旧 S7 的触发面不同 |
| V8 | 仅 `degraded==true` 要求 `degraded_recovery` | 条件未变，但编号跟着 V 表走，避免半套 S、半套 V |
| V9 | `metrics_auto.source=="auto"`，且整行 gate 只能由脚手架写 | 旧 S9 还认嵌在 task 里的 `gate.F3_proc`；v1.2 不认 |
| V10 | 折叠无环；`reviewer ≠ executor_id` | 新规则，不是旧 S10 |
| V11 | §6 自由文本边界 | 新规则 |
| V12 | `timed_out=true` 时该阶段 exit_code≠0 且 `result=FAIL`；task.acceptance 禁止 PASS/FAIL | 新规则 |
| V13 | 自测守卫：改 V 规则或校验器必须跑正反样例，未全绿不得合并 | 旧 S10 的后半句搬到这里 |

旧 S10 的前半句（legacy 豁免业务字段、不豁免序列）只保留在 §8，不再单独占一个 V 号。

## 8. 迁移

现有 14 行是 v1.0/v1.1 账。字段集与 v1.2 不是同一张表：没有 `executor_id`，gate 还嵌在 task 里，acceptance 上可能已有模型写入的 PASS/FAIL。给这 14 行补字段再降级，等于改历史，而且 Auto 字段无法诚实回填。

不补字段。不改这 14 行。不把它们降成 lite。

切割方式只有追加。在该分片追加一条，且只追加这一条：

```json
{"record_type":"schema","spec":"1.2","freezes_seq_lte":14}
```

`session_id`、`seq`、`ts` 仍由脚手架注入，并且遵守 V1。`freezes_seq_lte` 必须等于这条 schema 事件之前的最大 seq。写错即 V4 失败。一个分片只允许一条 `spec=="1.2"` 的 schema 事件。

schema 行字段：

| 字段 | 类型 | 写入方 | 约束 |
|---|---|---|---|
| record_type | string | Auto | 固定 `"schema"` |
| session_id | string | Auto | 本分片 |
| seq | int | Auto | 严格 +1 |
| ts | string | Auto | 切割时间 |
| spec | string | Auto | 固定 `"1.2"` |
| freezes_seq_lte | int | Auto | 0 或正整数，等于此前最大 seq |

读模型：

1. `seq <= freezes_seq_lte` 的行视为 legacy，即使行上没有 `legacy: true`。不回写这个标记。
2. legacy 行只跑旧 S1（seq / ts 单调）。不跑 V2–V13。
3. legacy 行不参与 §5 的 delivered / accepted / open。
4. schema 事件之后的新行全部按 v1.2，禁止再写 `legacy` 键。
5. 新会话的新文件先写 schema 行，`freezes_seq_lte: 0`，其后从下一个 seq 递增。

统计是两套，不要相加后叫做同一个「完全验收通过」：

| 集合 | 规则 |
|---|---|
| legacy | 只计行数，以及旧 S1 是否干净 |
| v1.2 | 只用 §5 的 delivered / accepted / open |
